# Проверка исходного состояния Helpdesk

Дата: 26 сентября 2026 года. Объект: каркас `0.1.0` для подготовки выпуска `v1.0.0`. После проверки он закреплён тегом `baseline-ek1`. Состав проверенных файлов указан в [source-sha256.json](source-sha256.json); изменения документации после проверки не меняют исходный код приложения.

## Среда и команды

Локальная среда — macOS arm64, Colima, Docker Engine 23.0.6, Docker Compose 2.18.1. Сборка вне контейнера выполнялась на Amazon Corretto 17.0.8; контейнерная сборка использует закреплённые образы Eclipse Temurin 17. Это описание фактической среды, а не рекомендация сохранять старый локальный JDK. PostgreSQL контейнера — 17.11, digest закреплён в Compose и тестах.

Основные зависимости: Kotlin 2.2.21, Spring Boot 3.5.16, Spring Security 6.5.11, Flyway 11.7.2, JUnit Jupiter 5.12.2, Testcontainers 1.21.4. Полный разрешённый состав находится в [gradle.lockfile](../gradle.lockfile). Проверка известных уязвимостей этих компонентов ещё не выполнена.

```sh
export DOCKER_HOST="unix://${HOME}/.colima/default/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
./gradlew clean test bootJar --no-daemon
python3 scripts/init_env.py
./scripts/compose.sh up -d --build --wait
python3 scripts/smoke.py
python3 scripts/check_docs.py
```

## Автоматическая регрессия

Пройдены 28 проверок, ошибок и пропусков нет. [tests.json](tests.json) получен из JUnit XML фактического запуска; он сохраняет названия сценариев, время и исход. Полный XML повторно получается в `build/test-results/test/`. Набор тестов использует реальные механизмы Spring Security и отдельную PostgreSQL; данные рабочей Compose-среды не затрагиваются.

## Контейнерный запуск и миграции

Полная сборка Docker выполняется из исходников, локально собранный JAR в образ не копируется. PostgreSQL автоматически инициализирует роль `helpdesk`, Flyway применяет V1. Контейнер приложения достигает healthy; реальный HTTP-сценарий выполняет вход, создание, назначение, внутреннюю заметку, решение, повторное открытие и выход.

Фактический итог HTTP-сценария сохраняется в [smoke.txt](smoke.txt), безопасный срез параметров среды и проверка перезапуска — в [runtime.json](runtime.json). Пароли, cookie, содержимое внутренней заметки и полный `docker inspect` не публикуются.

Проверка роли БД показала отсутствие `superuser`, `createdb` и `createrole`. Приложение работает от UID/GID 10001. БД не публикует порт, API привязан к `127.0.0.1`. Файловая система приложения доступна только для чтения, временные файлы размещаются в ограниченном tmpfs.

Сохранение учебных записей и отсутствие повторного применения миграции проверены перезапуском. Это проверка именованного тома; она не подтверждает наличие резервной копии или способность восстановиться после удаления тома.

## Исправления при подготовке

Первый запуск тестов на старой Colima выявил задержку проброса порта после готовности PostgreSQL. Добавлено явное ожидание TCP-порта. При закреплении образа обнаружена особенность разбора `tag@digest` в Testcontainers 1.x; для теста используется эквивалентная ссылка `postgres@digest`. После исправления повторена полная регрессия.

Отдельным просмотром устранена возможность рассогласования проверки назначенного специалиста и чтения сообщений при одновременном повторном открытии: чтение подробностей удерживает блокировку строки в одной транзакции. Дополнительно уточнены ответы на неподдерживаемые методы и форматы. Эти изменения относятся к подготовке baseline, а не к будущему улучшению ЭК2.

## Что результат не подтверждает

Не выполнены полный SAST/SCA/DAST, формирование SBOM, эксплуатационные нагрузочные проверки и независимый аудит. Нет свидетельства запуска GitHub Actions до публикации. Успешная регрессия не означает отсутствия всех уязвимостей и не разрешает публичный запуск. Обоснованные ограничения и план дальнейших методов сохранены в разделах 3–5 `project.md`.
