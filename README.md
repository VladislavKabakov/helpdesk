# Helpdesk — учебный сервис обращений

Небольшой серверный сервис на Kotlin и Spring Boot. Пользователь создаёт обращение и общается со специалистом. Специалист принимает обращение, ведёт переписку, добавляет внутренние заметки и фиксирует решение. Пользователь может повторно открыть обращение.

Материалы ЭК1 находятся в [project.md](project.md). Объект ограничен локальной учебной средой с искусственными данными. Полноценного интерфейса, регистрации, почты и вложений нет.

## Быстрый запуск

Нужны Docker Engine с Docker Compose v2, Python 3 и доступ в интернет для первой сборки. На macOS подходят Colima или Docker Desktop. Java на компьютере для Docker-запуска не нужна.

Из корня этого репозитория:

```sh
# Только для Colima, если она ещё не запущена:
colima start --cpu 2 --memory 4

python3 scripts/init_env.py
./scripts/compose.sh up -d --build --wait
python3 scripts/smoke.py
```

Скрипт `compose.sh` поддерживает и `docker compose`, и отдельную команду `docker-compose`. После скачивания образов первая сборка может занять несколько минут. Успешная проверка заканчивается строкой `PASS`. API доступен на `http://127.0.0.1:8080`; `/health` возвращает состояние процесса. База данных не публикует порт на компьютер.

Если порт 8080 занят, добавьте `APP_PORT=18080` в `.env`, повторите запуск и выполните `python3 scripts/smoke.py --base-url http://127.0.0.1:18080`.

При первом запуске PostgreSQL создаёт отдельную роль приложения без прав суперпользователя, создания баз и ролей. Flyway автоматически применяет SQL из `src/main/resources/db/migration/`. Вручную создавать таблицы не нужно. Повторный запуск проверяет контрольные суммы миграций и не применяет V1 заново. Новые изменения схемы добавляются новыми файлами V2, V3 и далее; уже применённые миграции не редактируются.

## Тестовые учётные записи

`alice` и `bob` — пользователи, `agent1` и `agent2` — специалисты. Пароли случайно создаются в локальном `.env`. Скрипт не печатает их и не перезаписывает существующий файл. Посмотреть значения для ручного входа можно в редакторе; добавлять `.env` в Git нельзя.

Учебные учётные записи создаются только при `DEMO_ENABLED=true`; в данной Compose-конфигурации этот режим включён явно. При повторном старте существующие пароли не меняются. Если изменить `.env` после создания тома, пароль в базе сам не обновится. Для полностью новой учебной среды нужно осознанно удалить её том, как описано ниже.

`smoke.py` выполняет настоящий вход, работает с cookie и токеном защиты от поддельных запросов (CSRF), проверяет изоляцию и внутреннюю заметку. При каждом запуске он создаёт одно учебное обращение. Секреты и содержимое заметки в вывод не попадают. Описание ручных запросов: [docs/api.md](docs/api.md).

## Остановка, сохранение и удаление данных

```sh
./scripts/compose.sh stop
./scripts/compose.sh start
./scripts/compose.sh ps
./scripts/compose.sh logs --tail 50 app
```

Данные находятся в именованном томе `course-helpdesk_db-data`. Остановка, перезапуск и `down` сохраняют его. Сессии хранятся в памяти приложения: после его перезапуска нужно войти заново.

**Следующая команда удаляет все учебные обращения, пользователей и пароли проекта:**

```sh
./scripts/compose.sh down -v
```

После удаления тома `up` создаст схему заново. Команда не предназначена для среды с ценными данными.

## Сборка и автоматические тесты

Нужны JDK 17 и работающий Docker. Gradle установленным быть не обязан: используется Wrapper с проверкой SHA-256 дистрибутива.

```sh
./gradlew clean test bootJar --no-daemon
python3 scripts/check_docs.py
```

Для Colima перед Gradle задайте:

```sh
export DOCKER_HOST="unix://${HOME}/.colima/default/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
./gradlew clean test bootJar --no-daemon
```

Тесты поднимают отдельный контейнер PostgreSQL через Testcontainers и удаляют его после выполнения. Рабочий том Helpdesk они не используют. Нет подмены PostgreSQL на H2 и нет молчаливого пропуска тестов при недоступном Docker. Результаты: `build/reports/tests/test/index.html` и `build/test-results/test/`.

В бесплатной IntelliJ IDEA откройте `settings.gradle.kts` как Gradle-проект и выберите JDK 17. Для обычной проверки используйте задачу `test`, для сборки — `bootJar`. Для запуска из IDE потребуется доступная PostgreSQL и переменные `DB_URL`, `DB_USER`, `DB_PASSWORD`; рекомендуемый путь демонстрации — Compose.

## Ограничения учебного запуска

Порт приложения привязан к loopback. HTTP и cookie без признака Secure допустимы только для этого локального сценария. Публичный сервер, реальные обращения, TLS, резервное копирование, ограничение частоты входа и эксплуатационное наблюдение в эту поставку не входят. Изменение адреса на `0.0.0.0` не превращает её в готовый публичный сервис. Остальные ограничения и приоритеты описаны в [разделе 3 проекта](project.md#3-текущее-состояние).
